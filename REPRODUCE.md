# Reproducing the HARVI-ECG evaluation

Set the roots once; all scripts read them from the environment:

```bash
export PROJECT_ROOT=/path/to/project     # contains data/, manifests/, results/, and the ecg_audit package
export FAIRECG_ROOT=/path/to/fairecg     # FairECG checkpoints and harness (fair_lora)
export HARVI_V2_ROOT=/path/to/harvi_v2   # original HARVI-ECG code, cache/ntprobnp, fold checkpoints
```

Containers: `nvcr.io#nvidia/pytorch:25.08-py3` plus `harvi_v2/requirements.txt` for HARVI-ECG inference, and the FairECG harness container for steps 4–6.

| step | script | what it does | output |
|---|---|---|---|
| 0 | `src/00_inventory_folds.py` | reproduces the harvi_v2 `GroupKFold(5)` patient folds and flags FairECG pretraining exposure | `harvi_pairs_folds.npz`, `harvi_pair_in_pretraining.npy` |
| 1 | `src/01_inventory_overlap_emory.py` | Emory ICD-10 phenotypes, case-ECG selection, control pool | `emory_cases_draft.parquet`, `emory_controls_draft.parquet` |
| c | `src/checks/lead_order_harvi_cache.py`, `src/checks/lead_integrity_emory.py` | confirms canonical lead order; detects Emory aVL/aVF = ∓III/2 | logs |
| 2 | `slurm/02_harvi_oof.sbatch` | out-of-fold inference with the original HARVI-ECG checkpoints | `oof_harvi/oof_predictions.csv` |
| c | `src/checks/oof_discrepancy_diag.py` (`slurm/checks_oof_discrepancy_diag.sbatch`, `slurm/02b_harvi_oof_xlstm205.sbatch`) | weight-load report, held-out vs in-sample AUROC, xLSTM version pin | `diag.json` |
| 3 | `src/03_merge_harvi_oof.py` | merges OOF predictions with folds, patient IDs and exposure | `harvi_oof_merged.csv` |
| 4 | `src/04_build_external_emory.py` | 4:1 age/sex-matched Emory sets; rebuilds aVL/aVF from I and II. Its EchoNext block is a legacy of the dropped secondary check in the HARVI pre-specification (§5, deviation 2) and is not used for any reported result; the EchoNext analysis follows `docs/echonext_preregistration.md` | `external/ext_ecg.npy`, `ext_meta.parquet` |
| 5 | `slurm/05_harvi_external.sbatch` → `src/05_harvi_external_zeroshot.py` | zero-shot HARVI-ECG on Emory (5-fold mean) | `pred_harvi_ext.npz` |
| 6 | `slurm/06_fairecg_lora_fold.sbatch`, `slurm/06b_fairecg_frozen.sbatch` → `src/06_fairecg_harvi_heads.py` | FairECG + HARVI heads per fold (LoRA; frozen ablation); epoch selected on inner 10 % of training patients | `fairecg/pred_*.npz` |
| 7 | `src/07_export_for_scoring.py` | compact export for scoring | `score_export.npz`, `score_emory_meta.csv` |
| 8 | `scoring/harvi_score.py` | pre-specified scoring, 2,000 patient-bootstrap draws, seed 0 | `results/*.csv` |
| 9 | `report/build_report.py` | LaTeX report (text and tables generated from `results/`; final figures in `report/`, drawn from the plotted data exported by the scoring step) | `report/` |

Steps 8–9 need only the three export files from step 7. Put them in a folder and run:

Run from the repository root:

```bash
export HARVI_DATA=/path/to/exports
python scoring/harvi_score.py
python report/build_report.py
(cd report && pdflatex harvi_results_report.tex && pdflatex harvi_results_report.tex)
```

The scoring is deterministic (seed 0). Re-running `scoring/harvi_score.py`, `scoring/echonext_score_surrogate.py`, `scoring/echonext_score_direct.py` and `scoring/operating_points.py` on the exported predictions reproduces the CSVs they write in `results/` (checked for `operating_points.csv` against the released file). The report figures and the website are not regenerated by this repository: the figures in `report/` were drawn from the plotted data exported by the scoring step, and `docs/index.html` embeds the aggregate data in `docs/site_data.json`.

**Provenance of the EchoNext NT-proBNP intervals.** The report's Table 4 takes the NT-proBNP readout's AUROC and 95 % CI from `results/echonext/echonext_surrogate_auroc.csv` (`report/build_report.py` asserts the point estimate against the paired file). `results/echonext/echonext_direct_vs_surrogate.csv` repeats the same point estimates with slightly different intervals, because its bootstrap draws rows in a different order; its paired differences (SHD module − NT-proBNP readout) are the ones reported. The website and README use the Table 4 intervals.
Python packages for scoring and the report: numpy, pandas, scipy, scikit-learn, matplotlib, and pyarrow (the EchoNext scripts and `scoring/operating_points.py` read parquet files). The report compiles with pdflatex (TeX Live).

## What this release contains

| | In this repository | Needs approved access | Needed for |
|---|---|---|---|
| Evaluation and scoring code (`src/`, `scoring/`, `slurm/`) | yes | | everything |
| Aggregate results (`results/`), report, website | yes | | — |
| Patient-level exports (step 7 outputs, EchoNext predictions) | no | MIMIC-IV / MIMIC-IV-ECG and Harvard-Emory ECG Database (PhysioNet credentialing); EchoNext data-use agreement | re-scoring (steps 8–9, operating points) |
| Model weights (encoder, NT-proBNP readout, SHD module) | no | gated Hugging Face repository, manual approval | inference |
| Training stack (`ecg_audit` container, `fair_lora`, FairECG pretraining code, `harvi_v2` baseline code) | no | internal, unpublished | steps 0–7 (re-training and inference) |

Scoring (steps 8–9) needs only the exported predictions and the Python packages listed above. Full re-training additionally needs the unpublished training stack and is not provided as a standalone package. Conventions used throughout: patient-grouped `GroupKFold(5)` on MIMIC-IV; canonical 12-lead order, checked by `src/checks/`; Emory aVL/aVF rebuilt from I and II; age bands < 50, 50–75, > 75 years for the age-adjusted rule-in; one ECG per patient in all external test sets.

## Project website
`docs/` is served by GitHub Pages (Settings → Pages → branch `main`, folder `/docs`). `docs/index.html` renders every number from the JSON embedded in it (`docs/site_data.json` is the same data). After rebuilding the report, copy it to `docs/report/harvi_results_report.pdf`, where the site's report button links.
